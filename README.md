# GOG Vault

GOG Vault is a Windows x64 and Linux x64 desktop archive manager for offline installers from games you own on GOG. Tauri 2 hosts the React interface; a bundled Bun/TypeScript sidecar handles the GOG API, SQLite, downloads, scanning and checksum verification. No Docker service or separately installed Bun runtime is required to run the packaged app.

## Install and Develop

Use the Windows NSIS installer, Windows portable ZIP, or Linux `.deb`/AppImage produced by the Desktop CI workflow. Extract the portable ZIP before running `gog-vault.exe`; keep `gog-vault-sidecar.exe` beside it. Portable means no installer, not that account/queue settings travel with the ZIP: they live in the Windows user profile. Windows needs WebView2 (present on current Windows 10/11); Linux needs the distribution's WebKitGTK 4.1 runtime. CI binaries are unsigned; Windows may show a SmartScreen warning. Do not run untrusted binaries.

For development, install [Bun](https://bun.sh), [Rust](https://rustup.rs) and the [Tauri platform prerequisites](https://v2.tauri.app/start/prerequisites/). Windows needs MSVC C++ Build Tools and WebView2; Ubuntu needs WebKitGTK 4.1, appindicator, OpenSSL and librsvg development packages. Then:

```sh
bun install
bun run dev
```

`bun run dev` compiles the local Bun sidecar, starts Vite, and runs Tauri; when the desktop window closes, it closes Vite cleanly. Run development through this command rather than invoking `tauri dev` directly. `bun run build` compiles the sidecar and packages the native application; `bun run portable` builds the Windows NSIS installer and portable ZIP on Windows x64. `bun run test`, `bun run typecheck`, `bun run build:web` and `bun run sidecar` run individual checks/builds. Tests use Bun's per-file isolation for mocked dependencies. Windows and Linux installers must be built on their respective operating systems. Sidecar binaries are generated and ignored by Git.

## First Use

Open Settings, choose a vault directory on a local disk or mounted network share with the native picker, and connect your GOG account. No archive directory is created until you select one. The Connect GOG button opens GOG's sign-in page in a temporary desktop window; enter your password and 2FA **only on GOG**. The app intercepts the redirect and completes the connection automatically. If GOG does not support your desktop WebView, choose **Use browser instead**, open GOG in your default browser, and paste the resulting redirect URL or authorization code. Refresh the library, then scan an existing archive or select installers to download.

The library includes logo tiles and a compact list, platform/status filters, sorting, download selectors and per-game manifests. Main/DLC/Extras completion is byte-weighted. N/A means no content exists; OFF means optional content exists but is not selected; 0% means selected content is missing. DLC products remain separate Library cards with their own artwork, installers, local size, hidden state and CONTENT progress. The parent references selected owned child products for its DLC progress and download/verification actions; unselected child DLC and extras do not block Vaulted. Parent card Local Size counts only its own files; the DLC card counts its own files, including legacy installers still stored in the parent folder. Each physical file contributes once to global Vault Size. The persistent download queue supports pause/resume/cancel, HTTP Range `.part` resumes, retries and checksums. Its error details identify the failing file, part, stage and HTTP status without exposing signed URLs. When GOG provides no checksum, a completed size-matched download records a local SHA-256 and is labeled separately from GOG checksum verification. Offline metadata and artwork are stored in each game folder. Selected-content manifest changes indicate available updates; same-name installers from a prior version move into `.gog-vault/previous` only after the replacement verifies. No update starts automatically. Closing the main window quits GOG Vault and stops its sidecar; unfinished downloads can resume on the next launch.

Settings allow multiple default platforms and languages and optional DLC, extras, patches, language packs, and media archival. Per-game selections are saved independently; changing defaults does not rewrite existing selections or queued job snapshots. The Library's **Download missing** action previews selected files before queueing them. Library refresh and **Scan Directory** at launch are opt-in and do not start downloads. Store media can be viewed without archiving it; selected official media may be saved alongside a linked game. Cached artwork keeps separate card, hero, logo, and icon roles; media metadata includes the original source URL, local path, measured image dimensions, and MIME type when available. Set `GOG_VAULT_DEBUG_MEDIA=1` during development to log public image URLs and measured dimensions without credentials.

The chosen vault directory is saved as an absolute path in SQLite. A disconnected network share is reported unavailable; GOG Vault does not recreate it, scan it as empty, or start queued downloads until it is accessible again. Files already in the archive are never removed by a scan. For existing folders with names different from the GOG title, use the native picker in game details to link a direct child of the vault. Back up both the chosen vault and the application data directory (including `vault.sqlite`, SQLite WAL files and `account.json`); stop the app for a consistent database copy. New Windows installs use Local AppData; existing Roaming AppData directories continue to be used so upgrades do not hide prior accounts and queues.

**Scan Directory** indexes local file names and sizes and identifies matching multipart installers without downloading them. A name/size match is shown as **Needs Verification**, not checksum-verified; use **Full Verify** when checksum metadata is available. Only a matching saved product ID or an exact title corroborated by installer name and size can auto-link. Other folders appear in Settings as a count: **Review matches** shows ranked candidates, evidence, a product picker and a persistent per-vault **Ignore folder** action. Linking immediately scans existing files and removes the row without another directory scan. **Import Games** reviews folders outside the vault, requires a GOG product ID per folder, and defaults to COPY. Each file is SHA-256 checked before its staged copy becomes a managed vault folder; optional MOVE additionally requires typing MOVE, and source files are removed only after the copy commits and is verified. Neither mode overwrites an existing game folder. Keep an archive backup until the import is reviewed. **Organize vault** previews linked folder renames with both paths and conflicting product IDs, and changes a folder name only after confirmation. It does not rename installer files or move unlinked folders. Windows drive capacity comes from the native desktop runtime's 64-bit disk-space API, including UNC shares; it can be unavailable on some shares, while indexed vault size is reported separately.

**Vaulted** requires all selected content in the active vault to be verified; unselected extras do not count. A complete verified prior installer set may be Vaulted even when its current GOG manifest match is unknown. A changed manifest alone does not prove a newer version. **Full Verify** runs as a background Activity job with per-file progress and a cancel action; different games wait for the current verification. Active verification jobs are in memory, so a restart during verification requires starting a new job. Verified file evidence and final archive state remain in vault-scoped SQLite.

The Game Details gallery groups identical artwork into one thumbnail while retaining all semantic roles (such as CARD and HERO). Core images are saved under `.gog-vault/artwork`; existing app-managed artwork is migrated when metadata is refreshed, and old locations remain readable. Cached artwork and selected archived media record measured dimensions and SHA-256 hashes; small icons are not stretched to fill gallery tiles. Direct GOG MP4/WebM videos play in the viewer, with archived videos served through short-lived, scoped local tickets and byte ranges. Supported YouTube and Vimeo embeds play in the viewer without archiving provider video. The video archive default remains off and does not affect online viewing.

For an existing Docker installation, stop the container, copy its `/config` contents into the desktop app data directory, then select the old host-side `/vault` archive with the native picker. Keep the original archive and backup until the desktop library and queue have been checked. Resolve any old relative vault setting by selecting its absolute host path before resuming queued downloads.

Library visibility is local: Game Details confirms Hide from Library, and the Visible, Hidden, and All scopes search both sets. Hiding a game does not change ownership totals, GOG refresh, downloads, or the archive.

Imports run as persisted background jobs with file progress, stages, errors, cancellation, and retry. Interrupted COPY jobs retain their source and verified staging checkpoints. Do not retry a failed MOVE source-cleanup job without inspecting both locations.

Each selected vault has a separate local folder mapping, file inventory, verification state, imported media paths, and archive completion. GOG ownership and remote manifests remain global. Switching vaults is blocked while downloads, imports, or a vault scan are active; finish or cancel work first. Background jobs record their destination vault. Automatic scans recognize unlinked folders only when `.gog-vault/metadata.json` contains a matching GOG product ID; use Review Matches to confirm adoption of folders without metadata. An upgrade from older databases creates a timestamped `vault.sqlite.pre-vault-scope-migration-*` SQLite backup. Legacy mappings are adopted only when that selected vault's on-disk product metadata confirms the mapping; uncertain mappings remain in the backup and must be linked or adopted explicitly. Legacy jobs without a known destination vault are not resumed automatically.

DLC relationships are persisted by GOG product ID. A database upgrade also backs up existing SQLite state before identifying duplicate parent/child manifest entries by the child's product ID and exact remote key. Existing verified DLC bytes may stay in a parent's folder: a vault-scoped reference assigns the child the logical file without copying, moving or hashing it during migration. Ambiguous relationships and outstanding legacy queue snapshots are retained for review rather than discarded.

## Security and Data

Tauri starts the sidecar on a randomly assigned `127.0.0.1` port with a fresh 256-bit session token. Every HTTP API and queue WebSocket request requires that token, except archived-media GET requests carrying an expiring ticket scoped to one media asset. The session token is sent to the frontend through a Tauri command and is never stored on disk. The built React app is served by Tauri, not by the API. Do not expose the sidecar over a network or reuse its token outside the desktop app.

GOG refresh credentials are stored in Windows Credential Manager or Linux Secret Service, not in the library database. A legacy `account.json` is deleted only after its credential has been saved and read back from the OS store. For previously encrypted installations, set the original `GOG_VAULT_SECRET_KEY` once during migration; it is not needed afterward. If the OS credential store is unavailable or locked, unlock or enable it before connecting. Disconnect removes the stored credential, but leaves the library and archive untouched. An authenticated user can select any directory writable by their OS account, so use only trusted archives and keep backups protected.

GOG Vault is independent and not affiliated with GOG. Download and retain only content your account may access. GOG's APIs can change; the adapter lives in `src/server/gog/` and the included tests use fixtures rather than credentials.
